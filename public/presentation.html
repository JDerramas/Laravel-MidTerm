The Problem Statement

Manual Logistics Inefficiencies & Friction

Bakit kailangan palitan ang traditional paper forms at shared Google Sheets?

Bottleneck 1
❌ Fragile Spreadsheets & Lost Orders
  • Madalas mabura, ma-overwrite, o mawala ang rows sa shared Excel/Google Sheets.
  • Typo sa student numbers at unverified proof of payments via screenshot.
  • Walang centralized record ng real-time transactions.
Bottleneck 2
❌ Double-Booking & Size Stockouts
  • Walang atomic allocation bawat size (XS hanggang 3XL).
  • Sabay-sabay na umoorder ang students kaya nagkaka-overselling ng Medium o Large.
  • Nalalaman lang na ubos na ang stock kapag pipila na sa physical distribution counter!
Bottleneck 3
❌ Premature Releases & Counter Chaos
  • Nagkakaroon ng gulo sa releasing counter kapag may mali sa size o may dispute.
  • Nai-release ng counter officer ang uniform nang hindi pa verified ang GCash reference.
  • Walang mechanism para pigilan ang release kapag may complaint ang estudyante.
Bottleneck 4
❌ Identity Spoofing & Credential Fatigue
  • Kailangang gumawa ng bagong password sa bawat website na madalas makalimutan.
  • Pwedeng magpanggap ang ibang estudyante gamit ang student number ng iba.
The Engineered Solution

End-to-End Automated Merchandise Portal

Apat na pangunahing engineering innovations na binuo sa aming system:

🔐
1-Click OnePass SSO
Direktang naka-integrate sa institutional campus server gamit ang OAuth 2.0 / OIDC with PKCE S256. Zero password needed!
📦
Atomic Inventory Control
Bawat size ay may dedicated counter. Protektado ng database locks para imposibleng magka-overselling o double-booking.
⚡
3-Second Live Polling
Kusang nag-uupdate ang Admin Order Queue tuwing 3 segundo nang hindi nag-rerefresh o nagla-lag ang buong page.
🛡️
Automated Conflict Lock
Kapag nag-file ng ticket ang estudyante, automatic magiging ⚠️ ON HOLD ang order para hindi mai-release nang mali.
✨ Result: Zero manual calculations, 100% verified digital receipts, and completely seamless campus distribution! Enterprise Ready

Database Design & Data Integrity

Normalized Schema & JSON Snapshot Pattern

Pitong (7) normalized tables na may strict ACID compliance at relational cascades:

7 Normalized Tables
  • products: Dynamic JSON size counters at stock per item code.
  • reservations: Student checkout details na may frozen cart snapshot.
  • support_tickets: Customer inquiry tracking (Open, In Review, Resolved).
  • support_messages: Turn-taking chat thread with ON DELETE CASCADE.
  • system_users: Role-based admin directory para sa mga opisyales.
  • students: Verified student accounts na naka-cache mula sa OnePass.
  • activity_logs: Immutable security audit trail ng lahat ng actions sa system.
Key Engineering Highlights
🔒 Frozen Cart JSON Snapshot Pattern:

Sine-save ang buong cart as JSON string sa loob ng reservation table para kahit magbago ang presyo ng produkto sa hinaharap, hindi magagalaw ang historical receipt ng estudyante.

⚡ Cascading Foreign Keys:

Kapag binura ang ticket, kusang nabubura ang mga kaugnay na chat messages para walang maging orphan data sa database.

🛡️ Database Transactions (DB::beginTransaction):

Ginagarantiyahan na magkasabay mabawasan ang stock at ma-create ang resibo nang walang conflict.
