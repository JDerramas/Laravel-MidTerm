I. EXECUTIVE OVERVIEW (ANO ITO AT BAKIT GINAWA?)
--------------------------------------------------------------------------------
Sa proyektong ito, in-integrate natin ang ICS Merch Portal sa central campus 
identity provider na "OnePass" (https://onepass-gdbe.onrender.com). 

Bakit hindi na lang ordinaryong login form na may password sa database?
1. SINGLE SIGN-ON (SSO): Isang account lang ang kailangang tandaan ng estudyante 
   sa buong pamantasan.
2. ZERO PASSWORD EXPOSURE: Ang ICS Merch Portal ay HINDI kailanman humahawak o 
   nagtatago ng passwords ng estudyante. Si OnePass ang nagbe-verify ng credentials.
3. OFFICIAL STUDENT VERIFICATION: Tanging mga lehitimo at enrolled na estudyante 
   na may active student number at email (hal. @npc.edu.ph) ang makakapag-reserve.
4. ENTERPRISE SECURITY STANDARDS: Gumamit tayo ng RFC 6749 at RFC 7636 (PKCE) 
   gamit ang SHA-256 cryptographic hashing.

III. PAANO GINAWA ANG "ENCRYPTION" AT SECURITY? (PKCE & SHA-256)
--------------------------------------------------------------------------------
Ang terminong "encryption" dito ay tumutukoy sa RFC 7636 PKCE (Proof Key for 
Code Exchange) at Cryptographic One-Way Hashing gamit ang SHA-256.

Makikita ito sa: app/Http/Controllers/OAuthController.php (L28-L48)

--------------------------------------------------------------------------------
A. CODE VERIFIER (Ang Sikretong Susi)
--------------------------------------------------------------------------------
Bago i-redirect ang user, gumagawa ang Laravel ng random 64-character high-entropy 
cryptographic string:

   $codeVerifier = Str::random(64);
   session(['oauth_code_verifier' => $codeVerifier]);

* Ito ay pribadong sikreto ng browser session ng user. Hindi ito ipinapadala sa 
  authorization URL kaya walang sinumang makakakita nito habang nagba-browse.

--------------------------------------------------------------------------------
B. CODE CHALLENGE (Ang SHA-256 Encrypted / Hashed Box)
--------------------------------------------------------------------------------
Kukunin ng Laravel ang Code Verifier at isasalang sa SHA-256 algorithm:

   $rawHash = hash('sha256', $codeVerifier, true);
   $codeChallenge = rtrim(strtr(base64_encode($rawHash), '+/', '-_'), '=');

* Paano ito gumagana step-by-step?
  1. `hash('sha256', ..., true)`: Kinukalkula ang 256-bit binary hash.
     Dahil ito ay cryptographic one-way hash, IMPOSIBLENG ibalik o i-reverse-engineer 
     ang hash pabalik sa original verifier!
  2. `base64_encode(...)`: Kinokonvert ang raw binary bytes sa readable characters.
  3. `strtr(..., '+/', '-_')` at `rtrim(..., '=')`: Ginagawang "URL-Safe" ang string 
     (Base64URL encoding) alinsunod sa RFC 7636. Tinatanggal ang '+' at '/' para 
     hindi masira o mag-error sa web URL.

--------------------------------------------------------------------------------
C. CSRF PROTECTION (State Token)
--------------------------------------------------------------------------------
Gumagawa rin tayo ng 40-character random token:

   $state = Str::random(40);
   session(['oauth_state' => $state]);

* Proteksyon ito laban sa Cross-Site Request Forgery (CSRF). Pagbalik ni OnePass 
  sa ating callback, tinitingnan kung tumutugma ang state. Kung hindi match, 
  ibig sabihin ay na-tamper ang request at agad itong ibabagsak ng system.

IV. ANG BUONG 4-STEP OAUTH 2.0 HANDSHAKE FLOW
--------------------------------------------------------------------------------

[Estudyante]             [ICS Merch (Laravel)]           [OnePass (Render Cloud)]
     |                             |                                    |
     | 1. Click "Student Login"    |                                    |
     |---------------------------->|                                    |
     |                             | Gen: Verifier + SHA256 Challenge   |
     |                             | Redirect to OnePass Auth URL       |
     | 2. Redirect to OnePass      |----------------------------------->|
     |<-----------------------------------------------------------------|
     |                             |                                    |
     | 3. Login sa OnePass Portal  |                                    |
     |    (Email & Password)       |                                    |
     |----------------------------------------------------------------->|
     |                             |                                    |
     | 4. Redirect with ?code=XYZ  | OnePass approves & redirects       |
     |---------------------------->|                                    |
     |                             |                                    |
     |                             | 5. Backchannel Token POST Request  |
     |                             |    (code + verifier + secret)      |
     |                             |----------------------------------->|
     |                             |                                    |
     |                             | 6. OnePass verifies SHA256 match   |
     |                             |    Returns access_token + id_token |
     |                             |<-----------------------------------|
     |                             |                                    |
     |                             | 7. Decode JWT Claims (0ms)         |
     |                             |    Save to session('student_user') |
     | 8. Show Logged-in Profile   |    Cache to local 'students' table |
     |<----------------------------|                                    |

--------------------------------------------------------------------------------
DETALYE NG BAWAT STEP:

STEP 1: Pag-redirect papuntang OnePass (/oauth/login)
- Tinatawag ang `OAuthController::redirect()`.
- Nagtatayo ng request papuntang `https://onepass-gdbe.onrender.com/oauth/authorize`
- Kasama ang parameters:
  * `client_id`: ID ng ating application
  * `redirect_uri`: http://127.0.0.1:8000/oauth/callback
  * `response_type`: code
  * `scope`: openid profile email student_id qr contact avatar
  * `state`: $state
  * `code_challenge`: $codeChallenge
  * `code_challenge_method`: S256

STEP 2: Pag-login ng User sa OnePass
- Sa OnePass portal mag-eenter ang estudyante. Ligtas ang credentials.
- Kapag valid ang account, magge-generate si OnePass ng short-lived `code`.

STEP 3: Pagbabalik sa Callback (/oauth/callback)
- Ire-redirect ni OnePass ang user pabalik sa http://127.0.0.1:8000/oauth/callback?code=AUTH_CODE_RECEIVED.
- Sinusuri ng ating controller kung may error o wala ang code.

STEP 4: Backchannel Token Exchange (Server-to-Server POST)
- Sa backend (walang nakikitang URL sa browser), magpapadala ang Laravel ng 
  HTTP POST sa `https://onepass-gdbe.onrender.com/api/oauth/token`:
  * `grant_type`: authorization_code
  * `code`: AUTH_CODE_RECEIVED
  * `redirect_uri`: http://127.0.0.1:8000/oauth/callback
  * `client_id`: Registered client ID
  * `client_secret`: Registered secret key
  * `code_verifier`: Yung unhashed 64-character string mula sa session!
- I-hahashe ni OnePass ang `code_verifier` gamit ang SHA-256. Kung match sa 
  `code_challenge` na natanggap sa Step 1, ibibigay ni OnePass ang:
  * `access_token`
  * `id_token` (Signed OpenID Connect JWT)

STEP 5: Pagbasa ng Student Data (Zero-Latency JWT Decoding)
- Sa halip na maghintay pa sa mabagal na internet request, binabasa agad ng 
  Laravel ang `id_token` JSON Web Token (JWT) sa pamamagitan ng base64 decoding:
  * Pangalan (`name`)
  * Student Number (`student_id`)
  * Email (`email`)
  * Kurso / Departamento (`course`)
  * Taon at Seksyon (`year_level`, `section`)
  * Contact Number (`contact_number`)
  * Digital QR Membership Code (`qr_payload`)

V. INTEGRATION SA LOCAL DATABASE AT ADMIN AUTHORIZATION
--------------------------------------------------------------------------------

1. LOCAL STUDENT CACHING (students table):
   Kapag nag-login ang estudyante, tinatawag ang:
   \App\Models\Student::updateOrCreate(
       ['student_id' => $studentId],
       [
           'name'       => $name,
           'email'      => $email,
           'department' => $course,
           'section'    => $section,
           'year_level' => $yearLevel,
           'avatar'     => $avatar,
           'status'     => 'Enrolled',
       ]
   );
   Dahil dito, may permanenteng record ang ICS database ng bawat estudyanteng 
   pumasok sa reservation system.

2. AUDIT TRAIL LOGGING (activity_logs table):
   Awtomatikong nagtatala ng security log:
   ActivityLog::record(
       'LOGIN',
       "Student [{$name} ({$studentId})] authenticated successfully via OnePass OIDC SSO.",
       $studentId,
       $name
   );

3. SESSION MANAGEMENT:
   Itinatabi ang buong profile sa `session(['student_user' => $studentProfile])`.
   Ito ang nagpapakita ng:
   - Profile avatar pill sa header navigation
   - Student ID, Name, at Section
   - "View OnePass Profile" link
   - "Admin Management Console" link

4. ADMIN ROLE-BASED ACCESS CONTROL (RBAC):
   Makikita sa: app/Http/Controllers/MerchController.php (L100-L115)
   
   Kapag pinindot ang "Admin Management Console" (/admin):
   a. Tinitingnan muna kung naka-login ang user via OnePass (`session('student_user')`).
   b. Kinukuha ang email ng user (hal. `ics@npc.edu.ph`).
   c. Tinitingnan sa local table na `system_users`:
      SystemUser::where('email', $userEmail)->where('status', 'Active')->first();
   d. KUNG AUTHORIZED:
      Papapasukin siya sa buong Admin Management Console (Dashboard KPIs, 
      Products CRUD, Reservation Queue, Sales Reports, Activity Logs, Helpdesk).
   e. KUNG HINDI AUTHORIZED:
      Ibo-block siya at magpapakita ng malinis na red alert:
      "Access Denied: Your account (email) is not authorized as an Administrator..."

VI. DEFENSE SCRIPT AT TALKING POINTS (PARA SA PRESENTATION)
--------------------------------------------------------------------------------

SCRIPT / INTRO SA PANEL:
"Magandang araw po sa ating panel at guro. Ang aming authentication system ay 
hindi po ordinaryong standalone login form kung saan nag-iimbak kami ng mga 
plain passwords sa database. Sumunod po kami sa enterprise security protocols: 
ang RFC 6749 (OAuth 2.0), RFC 7636 (PKCE), at OpenID Connect Core 1.0 gamit ang 
official campus Identity Provider na OnePass."

SAGOT SA MGA POSIBLENG ITANONG:

1. Tanong: "Bakit kailangan pa ng PKCE kung may Client Secret naman?"
   Sagot: "Sir/Ma'am, ang PKCE o Proof Key for Code Exchange ay binuo para sa 
   public clients at web apps upang maiwasan ang Authorization Code Interception 
   Attack. Bago mag-redirect sa OnePass, gumagawa ang aming Laravel backend ng 
   isang 64-character random Code Verifier, at ini-encrypt ito gamit ang SHA-256 
   one-way hash (S256 challenge). Kahit may sumubok humarang o sumilip sa code 
   sa browser redirection, hindi nila magagamit ang code dahil wala sa kanila 
   ang unhashed Code Verifier na nasa server session lang namin."

2. Tanong: "Paano niyo nakuha yung data ng student galing sa OnePass?"
   Sagot: "Pagkatapos pong mai-verify ni OnePass ang code at PKCE verifier, 
   nagbibigay po ito ng OpenID Connect ID Token (JWT). Ang JWT po na ito ay 
   may cryptographically signed payload na naglalaman ng student identity claims 
   tulad ng Name, Student ID, Email, Course, at Section. Dinedecode po ito 
   ng aming server nang 0ms gamit ang Base64 decoding at sine-save sa aktibong 
   session at sa aming local `students` database table."

3. Tanong: "Paano naging Admin ang isang OnePass account tulad ng ics@npc.edu.ph?"
   Sagot: "Pinaghiwalay po namin ang Authentication at Authorization alinsunod sa 
   Software Engineering best practices. Si OnePass po ang bahala sa Authentication 
   (pag-verify kung sino ka), habang ang aming local `system_users` table naman po 
   ang bahala sa Authorization (kung anong karapatan at role mo sa aming tindahan). 
   Kapag nag-login po ang `ics@npc.edu.ph`, chinecheck po ng aming MerchController 
   kung ang email niya ay nakarehistro bilang active Administrator sa `system_users`. 
   Kapag tugma, binubuksan po sa kanya ang buong Admin Management Dashboard."
