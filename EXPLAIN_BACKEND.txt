I. SIMPLENG PALIWANAG: ANO BA ANG ROLE NG BACKEND SA MVC?
--------------------------------------------------------------------------------
Isipin mo ang MVC na parang isang sikat na kainan o restaurant:

1. VIEW (Frontend - merch.blade.php & admin.blade.php):
   - Ito yung "Waiter" at "Menu".
   - May dalawa tayong hiwalay na views:
     * merch.blade.php -> para sa Student Store (Catalog, Cart, Checkout).
     * admin.blade.php -> para sa Admin Portal (Dashboard, Queue, CRUD, Logs).

2. ROUTE (routes/web.php):
   - Ito yung "Order Slip".
   - Sinasabi kung saang kusina o function dapat pumunta yung request ng user.

3. CONTROLLER (MerchController.php):
   - Ito yung "Chef / Kusinero".
   - Siya yung tumatanggap ng request mula sa routes, nagche-check kung valid,
     nag-uutos sa Model para mag-save o magbasa sa Database, at naghahanda
     ng tamang view o JSON data pabalik sa user.

4. MODEL (app/Models/*):
   - Ito yung "Pantry / Storage".
   - Siya yung direct na kumakausap sa MySQL tables gamit ang Eloquent ORM.

V. PALIWANAG SA PITONG (7) ELOQUENT MODELS AT KANILANG KONEKSYON SA CONTROLLERS
================================================================================
Directory: app/Models/
Teknolohiya: Laravel Eloquent ORM (Object-Relational Mapping)

Bakit mahalaga ang Models sa Backend?
Sa Laravel MVC, ang Model ang opisyal na tulay sa pagitan ng PHP code at ng MySQL database.
Sa halip na magsulat ng mapanganib at mahahabang raw SQL queries tulad ng:
`SELECT * FROM products WHERE id = 5` o `INSERT INTO reservations (...) VALUES (...)`,
ginagamit natin ang Eloquent Model syntax:
`Product::find(5)` o `Reservation::create([...])`.

Apat (4) na Dahilan Kung Bakit Konektado ang Models sa ating Controllers:
1. 100% SQL Injection Protection: Gumagamit ang Eloquent ng PDO prepared statements at parameter binding sa ilalim ng hood.
2. Mass Assignment Protection ($fillable): Pinipigilan ang hackers na magpasok ng unauthorized column updates (hal. pagbabago ng user role o ref_code).
3. Automatic Data Casting ($casts): Awtomatikong kino-convert ang JSON data types ng MySQL sa madaling gamiting PHP arrays (hal. cart items at size inventory counts).
4. Expressive Relational Queries: Nagbibigay daan sa malinis na table relationships (`hasMany`, `belongsTo`, `hasOne`) para sa aming Conflict Lock at Anti-Spam safety guards.

Narito ang detalyadong breakdown ng Pitong (7) Models at kung paano sila ginagamit ng Controllers:

     - Kinukuha ang unang titik ng First Name at Last Name (halimbawa: "Juan Dela Cruz" -> "JD") para sa avatar kapag walang uploaded picture.
   - `toProfileArray()`:
     - Nagbabalik ng malinis at kumpletong associative array ng estudyante na handang ilagay sa Laravel session (`session('student_user')`).

3. Paano Kumokonekta sa Controllers:
   a. Sa `OAuthController::callback()`:
      ```php
      \App\Models\Student::updateOrCreate(
          ['student_id' => $studentId],
          [
              'name'       => $name,
              'email'      => $email,
              'department' => $course,
              'section'    => $section,
              'year_level' => $yearLevel,
              'avatar'     => $avatar,
              'status'     => 'Enrolled',
          ]
      );
      ```
      - Pagkabalik ng estudyante mula sa OnePass SSO, awtomatikong ina-update o nililikha ng controller ang kanyang student record sa MySQL nang walang manual registration.
   b. Sa `OAuthController::logout()`:
      - Binubura ang session habang pinapanatili ang student profile sa database para sa mabilis na 1-click access sa hinaharap.

1-Paragraph Summary:
Basically, ang Student model ang humahawak ng verified credentials ng mga estudyante sa ating local database. Ginagamit ito ng OAuthController gamit ang updateOrCreate upang magsilbing mabilis na local cache na laging updated tuwing magsa-sign-in ang estudyante gamit ang OnePass.

================================================================================
VI. KABUUANG BUOD SA INTERACTION NG CONTROLLERS AT MODELS (THE MVC HARMONY)
================================================================================
Kapag tinanong ka sa defense: "Paano nagtutulungan ang inyong Controller at Model?"
Ito ang iyong isasagot:

"Basically po sa aming system, mahigpit naming sinusunod ang Single Responsibility Principle ng MVC:
1. Ang Controller ang 'Orchestrator' o 'Traffic Cop'—siya ang sumasala ng request, nagpapatakbo ng security checks tulad ng CSRF, Conflict Lock, at Anti-Spam turn-taking, at nagpapasya kung anong response ang ibabalik.
2. Ang Model naman ang 'Data Custodian'—siya ang nakikipag-ugnayan sa MySQL database gamit ang Eloquent ORM. Siya ang namamahala sa table casting (tulad ng JSON arrays para sa cart snapshots at size inventory), mass assignment security ($fillable), at table relationships (tulad ng activeTicket at messages).

Dahil dito, napapanatiling malinis, modular, ligtas sa SQL Injection, at madaling i-maintain ang aming buong backend architecture."
