IV. ASPEKTO 3: DEPLOYMENT CONFIGURATION, CLOUD HOSTING & SERVING
--------------------------------------------------------------------------------
1. Apache Web Server Configuration:
   - Sa XAMPP, ang buong project ay nakalagak sa `d:/xampp/htdocs/My_laravel`.
   - Security Root: Ang Apache document root ay dapat laging nakaturo sa `public/` directory
     (`public/index.php`) at hindi sa mismong project root.
   - Bakit sa `public/` lamang?
     Upang hindi direktang mabuksan ng sinumang estranghero sa browser ang `.env`,
     database migrations, o application controllers via URL path.

2. Storage Symlinking:
   - Command: `php artisan storage:link`
   - Paliwanag: Gumagawa ito ng symbolic link mula `storage/app/public` patungong `public/storage`.
     Dito ligtas na iniimbak ang mga GCash payment screenshot at merch image uploads
     nang hindi nakalantad ang core backend storage.

3. Optimization Commands Bago ang Defense:
   - `php artisan view:clear` (Nililinis ang lumang compiled Blade templates).
   - `php artisan config:clear` (Sinisigurong sariwa ang binabasang environment settings).
   - `php artisan route:clear` (Inia-update ang route table sa memory).

4. CLOUD DEPLOYMENT OPTIONS (KUNG KAILANGANG I-DEPLOY SA INTERNET):
   Kung kailangang i-deploy ang buong system para ma-access ng publiko:

   A. OPSIYON 1: RENDER.COM (Pinaka-bagay dahil dito naka-host ang OnePass)
      - Libreng Web Service na may auto-SSL/HTTPS (`https://app.onrender.com`).
      - Ikabit ang GitHub repository sa Render Web Service.
      - Para sa MySQL: Gamitin ang libreng cloud MySQL tulad ng Aiven.io o Clever Cloud.
      - I-set ang Environment Variables sa Render dashboard:
        `APP_ENV=production`, `APP_DEBUG=false`, `DB_HOST`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`.
      - I-update ang `ONEPASS_REDIRECT_URI=https://app.onrender.com/oauth/callback`.

   B. OPSIYON 2: RAILWAY.APP (Pinakamabilis para sa Laravel + MySQL)
      - 1-Click Provision ng MySQL Database.
      - Auto-deploy galing sa GitHub repo nang walang manual server configuration.

   C. OPSIYON 3: CLOUDFLARE TUNNEL (Instant Live Demo para sa Defense - Zero Gastos)
      - Kung kailangan lang i-demo bukas sa klase na accessible online sa CP o laptop ng prof:
        Patakbuhin ang command sa terminal:
        `cloudflared tunnel --url http://127.0.0.1:8000`
      - Bibigyan ka nito ng instant public secure link (hal. `https://xxxx.trycloudflare.com`).

   ⚠️ MAHALAGANG PAALALA SA ONEPASS OAUTH PAG-DEPLOY:
   - Sa OnePass, naka-whitelist ang callback URL. Kapag nagbago ang domain mula
     `http://127.0.0.1:8000/oauth/callback` papuntang live domain (e.g. `https://app.onrender.com/oauth/callback`),
     kailangang i-update ang `ONEPASS_REDIRECT_URI` sa `.env` at i-whitelist ang bagong URL sa OnePass Developer Portal.

Basically, ang deployment configuration ng aming system ay sumusunod sa pinakamahigpit na Laravel production standards. VI. ASPEKTO 5: SECURITY COMPLIANCE (PROTECTION CONTROLS)
--------------------------------------------------------------------------------
1. CSRF (Cross-Site Request Forgery) Protection:
   - Lahat ng AJAX POST, PATCH, at DELETE requests ay may kasamang `X-CSRF-TOKEN` header:
     `'X-CSRF-TOKEN': document.querySelector('meta[name="csrf-token"]').content`
   - Sinisiguro nito na ang bawat request ay nanggagaling lamang sa aming opisyal na website
     at hindi mula sa malicious third-party site.

2. SQL Injection Prevention:
   - 100% parameter-bound queries gamit ang Eloquent ORM.
   - Walang concatenating ng raw SQL strings (hal. walang `SELECT * FROM ... WHERE id = " . $id`).
   - Awtomatikong ine-escape ng PDO driver ang lahat ng input bago ibigay sa MySQL.

3. XSS (Cross-Site Scripting) Sanitization:
   - Ginagamit ng Blade ang double curly braces `{{ $variable }}` na awtomatikong tumatawag
     sa `htmlspecialchars()` upang i-convert ang `<`, `>`, at `&` sa harmless text entities.

4. Turn-Taking Anti-Spam Governance:
   - Pinipigilan ang Denial-of-Service (DoS) sa aming Helpdesk chat sa pamamagitan ng
     pag-lock sa student message input hanggang sa makasagot ang admin.

5. Data Deletion Compliance (Orphan Record Elimination):
   - Paggamit ng MySQL `ON DELETE CASCADE` constraint para awtomatikong linisin ang
     mga kaakibat na messages kapag binura ang resolved ticket.

→ 1-Paragraph Summary:
Basically, ang security compliance ng aming web application ay sumasaklaw sa limang antas ng proteksyon: CSRF token headers laban sa cross-site forgery, parameter binding laban sa SQL injection, Blade output escaping laban sa XSS attacks, turn-taking throttling laban sa chat spamming, at cascading foreign keys para maiwasan ang orphan data sa database.

VII. TOP 5 DEFENSE QUESTIONS PARA SA SYSTEM SUPPORT (AT MGA SAGOT)
--------------------------------------------------------------------------------

Q1: "Bakit kailangang nasa `public/` directory ang web server entry point at hindi sa root folder?"
A: "Kasi po sa root directory matatagpuan ang sensitibong mga files tulad ng aming `.env` na naglalaman ng database passwords, ang `/storage` logs, at ang `/app` source code. Kung sa root nakaturo ang web server, maaaring i-type ng sinuman sa URL bar ang `localhost/My_laravel/.env` at manakaw ang database credentials. Dahil sa `public/` nakaturo ang Apache, tanging ang `index.php` at mga public assets lamang ang maa-access mula sa labas."

Q2: "Paano ninyo na-verify na hindi magkakaroon ng SQL Injection sa inyong mga forms?"
A: "Sa buong `MerchController.php`, wala po kaming ginamit na kahit isang raw SQL query string. Lahat po ng database operations ay dumadaan sa Laravel Eloquent ORM tulad ng `Product::find($id)` at `Reservation::where('ref_code', $ref)->first()`. Ang Eloquent ay gumagamit ng PDO Prepared Statements na naghihiwalay sa SQL query structure at sa user data, kaya imposible itong pasukin ng SQL injection."

Q3: "Bakit hindi ninyo isinama ang `vendor/` folder at `.env` sa inyong Git repository?"
A: "Ang `vendor/` folder po ay naglalaman ng daan-daang megabytes ng third-party libraries na kayang-kayang i-download muli sa isang command lamang na `composer install`. Ang `.env` naman po ay naglalaman ng machine-specific settings at confidential passwords. Ang tamang software engineering practice po ay mag-commit lamang ng `.env.example` bilang template at hayaan ang bawat developer na mag-configure ng sarili nilang local `.env`."

Q4: "Ano ang mangyayari kung sabay-sabay na mag-checkout ang dalawang estudyante sa huling natitirang Medium polo?"
A: "Sinisiguro po ng aming backend controller transaction na atomic ang stock validation. Bago gumawa ng reservation record, sinusuri muna ang kasalukuyang bilang sa `sizes` column ng product. Ang unang request na pumasok ang makakabawas sa stock patungong zero; ang pangalawang request naman ay agad na makakatanggap ng validation error response na nagsasabing 'Out of Stock na po ang napiling sukat'."

Q5: "Paano ninyo tiniyak na gumagana ang inyong system sa mobile phones ng mga estudyante?"
A: "Ginamitan po namin ang buong frontend ng mobile-first responsive utilities mula sa Tailwind CSS. Sinubukan po namin ito sa mobile browser viewport gamit ang Chrome DevTools Device Mode sa iba't ibang screen resolutions tulad ng 375px at 414px. Ang aming shopping cart ay nagiging smooth sliding drawer mula sa gilid, ang reservation queue ay may horizontal scroll bar, at ang navigation ay may responsive dropdown menu."
