III. HALIGI 2: CODE COMMENTS AT PHPDOC / JSDOC STANDARDS
--------------------------------------------------------------------------------
1. Bakit mahalaga ang PHPDoc sa aming Backend (MerchController.php & Models):
   - Gumagamit kami ng formal PHPDoc annotations bago ang bawat controller method:
     ```php
     /**
      * Update order status with Conflict Lock verification.
      *
      * @param  \Illuminate\Http\Request  $request
      * @param  int  $id
      * @return \Illuminate\Http\JsonResponse
      */
     public function updateReservationStatus(Request $request, $id)
     ```
   - Malinaw kung anong data types ang tinatanggap (`@param`) at kung ano ang ibinabalik (`@return`).

2. Inline Business Logic Explanations:
   - Bawat komplikadong algorithm o business rule ay may descriptive comments:
     * Conflict Lock check: `// SAFETY GUARD: Check if reservation has an active support ticket`
     * Anti-Spam turn-taking: `// TURN-TAKING ANTI-SPAM: Lock input if last message was from student`
     * Deletion safety: `// DELETION GOVERNANCE: Allow delete only when status is Resolved`

3. JSDoc sa Client-Side Scripts (merch.blade.php & admin.blade.php):
   - Bawat JavaScript helper method ay may summary:
     ```javascript
     /**
      * Executes 3-second realtime polling and updates UI components.
      * @returns {Promise<void>}
      */
     async function fetchSyncData() { ... }
     ```

→ 1-Paragraph Summary:
Basically, ipinapatupad ng aming codebase ang PHPDoc at JSDoc commenting standards upang magkaroon ng self-documenting code. Ang bawat controller method, model cast, at complex security rule ay may malinaw na paliwanag sa parameters, return types, at business logic, na nagpapadali sa maintenance, code auditing, at IDE auto-completion.

VI. TOP 5 DEFENSE QUESTIONS PARA SA DOCUMENTATION (AT MGA SAGOT)
--------------------------------------------------------------------------------

Q1: "Bakit kailangan pa ng komprehensibong README.md kung mayroon naman kayong slides at explanation files?"
A: "Kasi po ang README.md ang opisyal na industry standard sa modern software engineering. Kapag ipinasa ang project sa GitHub o sa client, hindi sila titingin sa slides kundi sa README.md upang malaman ang installation steps, environment requirements, database setup, at API routes. Ito po ang nagbibigay ng agarang halaga at portability sa aming repository."

Q2: "Paano nakatulong ang PHPDoc comments sa inyong code quality?"
A: "Ang PHPDoc po ay nagbibigay ng mahigpit na structure sa aming functions sa pamamagitan ng pagdedeklara ng parameter types (`@param`) at return types (`@return`). Bukod sa mas madali itong basahin ng kapwa developers, tinutulungan din nito ang mga IDE tulad ng VS Code na makapagbigay ng accurate code intellisense at mabilis na mahuli ang type mismatch errors bago pa man patakbuhin ang code."

Q3: "Saan makikita ang system documentation kung sakaling magdagdag ng bagong developer sa inyong team?"
A: "Lahat po ng technical documentation ay naka-organisa sa aming repository. Ang README.md ay naglalaman ng core architecture at setup guide, habang ang inline PHPDoc comments sa controllers at models ay nagpapaliwanag ng logic ng bawat function. Mayroon din kaming dedicated explanation guides para sa Frontend, Backend, Database, at System Support para sa mabilis na developer onboarding."

Q4: "Bakit may mga visual ASCII diagrams pa sa inyong README at docs?"
A: "Dahil ang ASCII diagrams ay universal at platform-independent. Kahit buksan ito sa terminal, plain text editor, o GitHub markdown viewer, nananatili itong malinaw at hindi nagkakaroon ng missing image link issues. Agad na nakikita ng nagbabasa ang Cardinality at Foreign Key relationships ng aming 7 database tables sa isang tinginan lamang, pati na ang connection sa external Supabase cloud."

Q5: "Paano ninyo siniguro na updated ang documentation habang nagbabago ang inyong code?"
A: "Sumunod po kami sa practice na 'Code-and-Doc Synchronization'. Tuwing may idinadagdag o binabago kaming feature sa MerchController at OAuthController—tulad ng OnePass OAuth 2.0 PKCE S256 SSO, Supabase Auth synchronization, Turn-Taking Anti-Spam check, Conflict Lock warning, o Resolved Ticket Deletion—kaagad naming ina-update ang method comments, API routes table sa README.md, at ang anim (6) na kaukulang technical guides."
