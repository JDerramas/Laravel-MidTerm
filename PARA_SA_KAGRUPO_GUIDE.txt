II. PARA SA KAGRUPO MO NA NAKATOKA SA "SYSTEM SUPPORT" (TASK 4)
================================================================================
Tungkulin: Siya ang gaganap bilang DEVOPS ENGINEER, QA TESTER, at SECURITY OFFICER.
Dokumentong Babasahin Niya: EXPLAIN_SYSTEM_SUPPORT.txt

1. ANO ANG AMBAG / GAGAWIN NIYA BAGO ANG DEFENSE? (Para may actual ambag siya):
   -----------------------------------------------------------------------------
   a. MAG-TESTING (QA Tester Role):
      - Sabihan mo siyang mag-test sa website gamit ang iba't ibang devices (CP, laptop).
      - Ipa-test sa kanya:
        * Mag-order kapag 0 ang stock (dapat ma-block).
        * Mag-chat nang sunod-sunod sa support (dapat ma-lock dahil sa anti-spam).
        * Tingnan kung responsive sa phone screen niya.
      - Siya ang gagawa ng "QA Test Matrix" table (makikita sa EXPLAIN_SYSTEM_SUPPORT.txt).
   b. MAG-ARAL NG DEPLOYMENT (DevOps Role):
      - Pag-aralan niya kung paano i-deploy sa Render.com o Railway.
      - Pwede niyang i-install ang `cloudflared` sa laptop para siya ang mag-run ng:
        `cloudflared tunnel --url http://127.0.0.1:8000`
        para kapag humingi ang prof ng online link, siya ang magbibigay!

2. ANO ANG EXATONG SASABIHIN NIYA SA DEFENSE? (Kabisaduhin o Basahin Niya):
   -----------------------------------------------------------------------------
   "Magandang araw po. Ako po ang nakatoka sa System Support, Deployment, at Security.
   
   Sa aming environment setup, pinatakbo po namin ang system sa PHP 8.2+ gamit ang 
   XAMPP Apache web server. Siniguro po namin na ang Document Root ay laging nakaturo 
   sa `public/` directory upang hindi makita mula sa labas ang sensitibong `.env` file 
   at source code.
   
   Sa aspeto naman po ng Cloud Deployment, cloud-ready na po ang aming application. 
   Maaari po itong i-host sa Render.com—kung saan naka-deploy din ang aming OnePass 
   server—o sa Railway.app. Para naman po sa instant live evaluations, mayroon po 
   kaming Cloudflare Tunnel capability para maging accessible sa internet ang aming 
   server sa loob lamang ng ilang segundo nang may libreng SSL certificate.
   
   Sumailalim din po ang system sa 7 manual at boundary QA test scenarios kabilang 
   ang zero-stock blocking, GCash proof validation, chat turn-taking anti-spam, at 
   conflict lock verification kung saan 100% po itong pumasa.
   
   Sa Security naman po, 100% ng mutating requests ay protektado ng CSRF tokens, 
   parameterized queries laban sa SQL Injection gamit ang Eloquent ORM, XSS output 
   escaping sa Blade, at RFC 7636 PKCE S256 hashing sa OnePass authentication."

3. TOP 3 TANONG NA POSIBLENG IBATO SA KANYA NG PANEL (AT ANG ISASAGOT NIYA):
   -----------------------------------------------------------------------------
   Q1: "Bakit kailangang sa public folder nakaturo ang web server at hindi sa root?"
   A1: "Kasi po sa root directory nakatago ang `.env` na may database passwords at 
       application encryption key. Kung sa root nakaturo, pwedeng ma-download ng 
       estranghero ang `.env`. Sa pamamagitan ng `public/`, tanging ang `index.php` 
       at public assets lamang ang nakalantad."

   Q2: "Paano niyo na-deploy o balak i-deploy ang system niyo sa internet?"
   A2: "Ang aming OnePass Identity Provider po ay naka-host sa Render.com. Kaya 
       ang aming web application ay madali ring mai-deploy sa Render Web Service na 
       naka-link sa aming GitHub repository, habang nakakonekta sa cloud MySQL tulad 
       ng Aiven. Kailangan lamang pong i-update ang ONEPASS_REDIRECT_URI sa .env 
       para tumugma sa live domain."

   Q3: "Paano niyo napigilan ang spamming sa live chat helpdesk?"
   A3: "Ipinatupad po namin ang Turn-Taking Anti-Spam policy sa backend controller. 
       Kapag nag-send ang student ng mensahe, awtomatikong ila-lock ang kanyang chat 
       input. Hindi po siya makakapag-type muli hangga't hindi sumasagot ang admin."

1. ANO ANG AMBAG / GAGAWIN NIYA BAGO ANG DEFENSE? (Para may actual ambag siya):

   a. GUMAWA NG POWERPOINT SLIDES (Slide Deck Master):
      - Siya ang gagawa ng 7 slides sa PowerPoint o Canva base sa balangkas na nasa

        * Slide 2: Problem Statement (Manual logistics chaos)
        * Slide 3: Solution (ICS Merch Portal features)
        * Slide 4: 5-Layer Architecture Diagram

      - Alamin niya ang 21 API endpoints table at ang ASCII Entity-Relationship Diagram (ERD).
      - Siya ang magpapakita ng `README.md` at code comments sa screen kapag hinanap ng prof!

2. ANO ANG EXATONG SASABIHIN NIYA SA DEFENSE? (Kabisaduhin o Basahin Niya):
   -----------------------------------------------------------------------------
   "Magandang araw po. Ako naman po ang in-charge sa Project Documentation at Technical 
   Architecture Standards.
   
   Ang aming documentation po ay nakatayo sa apat (4) na haligi:
   Una, ang aming komprehensibong README.md. Ito po ang industry-standard blueprint 
   ng aming repository na naglalaman ng setup instructions, ASCII ERD schema diagram, 
   talaan ng 21 REST API endpoints, Cloud Deployment guides, at task distribution.
   
   Pangalawa, ang Code Documentation. Bawat public method po sa aming controllers 
   at Eloquent models ay sumusunod sa PHPDoc standards na may pormal na `@param` at 
   `@return` type annotations upang masiguro ang code intellisense at maintainability.
   
   Pangatlo, ang System Documentation Portfolio. Mayroon po kaming anim (6) na 
   nakalaang technical explanation guides para sa Frontend, Backend, Database, 
   System Support, OnePass Integration, at Presentation Guide upang maging malinaw 
   ang bawat module.
   
   Pang-apat, ang aming Presentation Materials. Ipinatupad po namin ang structured 
   na slide deck at turn-by-turn demo script upang maihatid nang maayos ang business 
   value at technical excellence ng aming proyekto sa harap ng evaluators."

3. TOP 3 TANONG NA POSIBLENG IBATO SA KANYA NG PANEL (AT ANG ISASAGOT NIYA):
   -----------------------------------------------------------------------------
   Q1: "Bakit kailangan pa ng README.md kung may slides naman kayo?"
   A1: "Ang README.md po ang opisyal na 'front door' ng repository ayon sa professional 
       software engineering practices. Kapag binuksan ang aming project sa GitHub, 
       ang README.md po ang nagbibigay ng agarang installation steps, database schema, 
       at API reference para mapatakbo agad ng kahit sinong developer ang system."

   Q2: "Paano nakatulong ang PHPDoc comments sa kalidad ng inyong code?"
   A2: "Ang PHPDoc comments po ay nagbibigay ng static typing structure sa PHP. 
       Dahil malinaw ang tinatanggap na parameter types at expected return types, 
       tinutulungan po nito ang IDE tulad ng VS Code na makapagbigay ng code 
       suggestions at maiwasan ang runtime type errors bago pa man mag-deploy."

   Q3: "Paano ninyo siniguro na updated ang inyong documentation habang nagko-code?"
   A3: "Sumunod po kami sa 'Code-and-Doc Synchronization'. Tuwing may idinadagdag 
       kaming bagong ruta o feature sa controllers—tulad ng OnePass PKCE S256 SSO, 
       Conflict Lock, o Reservation Deletion—kaagad po naming ina-update ang method 
       comments, ang REST API table sa README.md, at ang aming technical explanation files."
