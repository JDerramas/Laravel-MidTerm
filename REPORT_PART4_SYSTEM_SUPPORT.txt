TOPIC 5: SECURITY COMPLIANCE & BEST PRACTICES
--------------------------------------------------------------------------------
ANO ANG SASABIHIN MO:
"Pagdating po sa Cyber Security at Application Hardening, ipinatupad po namin 
ang sumusunod na mga pananggalang:

1. Cross-Site Request Forgery (CSRF) Protection:
   - Ang bawat POST, PUT, PATCH, at DELETE request ay may kasamang `@csrf` token o 
     `X-CSRF-TOKEN` HTTP header na bine-verify ng `VerifyCsrfToken` middleware.
2. SQL Injection Prevention:
   - 100% ng database access ay dumadaan sa Eloquent ORM na may PDO Parameter Binding. 
     Walang ginamit na raw string interpolation.
3. Cross-Site Scripting (XSS) Sanitization:
   - Ang lahat ng text na inilalabas sa Blade views ay gumagamit ng double curly braces `{{ ... }}` 
     na awtomatikong nagko-convert ng mapanganib na HTML tags (tulad ng `<script>`) 
     patungo sa ligtas na HTML entities gamit ang `htmlspecialchars()`.
4. OAuth 2.0 PKCE Security:
   - Gumamit po kami ng cryptographic `code_challenge` at `code_verifier` (SHA-256) 
     upang maprotektahan ang student authentication laban sa Man-in-the-Middle at 
     Code Interception attacks.
5. Password Hashing:
   - Lahat ng passwords sa database ay naka-hash sa pamamagitan ng Bcrypt algorithm."

IV. Q&A DEFENSE CHEAT SHEET (MGA POSIBLENG ITANONG NG PROF & SAGOT MO)
================================================================================
TANONG 1: "Bakit hindi ninyo isinama ang `.env` sa inyong GitHub repository?"
SAGOT MO:
"Dahil ang `.env` file po ay naglalaman ng 'sensitive environment secrets' tulad ng database 
passwords, OnePass client secrets, at APP_KEY. Kapag nai-push po ito sa Git, magiging bulnerable 
ang buong server sa security compromise. Ang tamang software engineering practice po ay ang 
pag-commit lamang ng `.env.example` at paglikha ng `.env` nang lokal sa bawat deployment machine."

TANONG 2: "Paano ninyo pinoprotektahan ang mga users laban sa Cross-Site Scripting (XSS)?"
SAGOT MO:
"Sa aming Laravel Blade views, ginagamit po namin ang `{{ $variable }}` syntax. Kusa po itong 
pinatatakbo ng Blade compiler sa `htmlspecialchars()` function ng PHP, kaya kung maglagay man 
ang isang malisyosong user ng `<script>alert('hack')</script>` sa chat o form, ire-render lamang 
ito ng browser bilang plain harmless text sa halip na i-execute bilang JavaScript code."

TANONG 3: "Bakit kailangan pa ng `php artisan storage:link`?"
SAGOT MO:
"Sa Laravel, ang mga in-upload na files tulad ng GCash receipts ay naka-imbak sa pribadong 
`storage/app/public/` folder para sa seguridad. Hindi po direktang ma-a-access ng web browser 
ang storage folder dahil ang Document Root ay nasa `public/`. Ang `storage:link` po ay gumagawa 
ng isang filesystem symbolic link (shortcut) mula sa `public/storage` patungo sa `storage/app/public`, 
upang mai-display ang mga larawan sa browser nang ligtas at maayos."
