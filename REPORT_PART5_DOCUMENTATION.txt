at client-side function ay may pormal na docstrings:

1. PHPDoc Standards sa Backend Controllers:
   - Sa `MerchController.php` at `OAuthController.php`, bawat function ay may structured docblock:
     * Nagpapaliwanag ng layunin ng method (method description);
     * Nagdedeklara ng accepted input parameters gamit ang `@param \Illuminate\Http\Request $request`;
     * Nagdedeklara ng expected return types gamit ang `@return \Illuminate\Http\JsonResponse`.
2. Inline Safety Guard Comments:
   - Kapag may kritikal na business rule, naglagay po kami ng inline explanatory comments.
   - Halimbawa sa stock verification:
     `// SAFETY GUARD: Check atomic current stock before order deduction`
   - O sa helpdesk anti-spam:
     `// TURN-TAKING ANTI-SPAM: Prevent student from spamming consecutive messages`
   - At sa unique constraint defense:
     `// DEFENSIVE RECONCILIATION: Match student by email or student_id to prevent collision`
3. JSDoc sa Client-Side Scripts:
   - Sa `merch.blade.php` at `admin.blade.php`, ang aming JavaScript functions tulad ng 
     `startRealtimeSync()`, `playAudioNotification()`, at `showToastAlert()` ay may malinaw

TOPIC 4: TECHNICAL INCIDENT MANAGEMENT & TROUBLESHOOTING LOGS
--------------------------------------------------------------------------------
ANO ANG SASABIHIN MO:
"Ang pang-apat na haligi po ay ang Technical Incident Management and Troubleshooting Logs.
Sa totoong software engineering po, normal na magkaroon ng errors sa staging at deployment. 
Ang mahalaga po ay kung paano ito na-record, na-analyze, at naresolba.

Naka-document po sa aming project records ang apat (4) na totoong errors na aming 
hinarap at matagumpay na naresolba:

1. Incident 1 - Docker DocumentRoot & Environment 500 Error:
   - Issue: 500 server error sa unang deploy sa Render.
   - Resolution: Na-document ang fix kung saan inilipat ang DocumentRoot sa `public/` 
     sa pamamagitan ng Dockerfile config, at nag-generate ng sariwang `APP_KEY`.
2. Incident 2 - OnePass OAuth 400 Bad Request:
   - Issue: Nag-fail ang redirect papunta sa login consent screen.
   - Resolution: Na-document ang synchronization ng exact Redirect URI 
     (`https://laravel-midterm-8n2y.onrender.com/oauth/callback`) sa OnePass Developer Portal 
     at ang exact scope alignment (`openid profile email student_id avatar`).
3. Incident 3 - SQLSTATE[23000] 1062 Duplicate Entry sa Login:
   - Issue: Unique constraint collision sa `students_email_unique`.
   - Resolution: Na-document ang Smart Lookup algorithm sa controller gamit ang 
     `where('email')->orWhere('student_id')` kasama ang defensive try/catch block.
4. Incident 4 - Activity Logs Real-Time Notifications & Sound Alerts:
   - Issue: Hindi kusa nagno-notify ang admin tuwing may mag-login o mag-logout.
   - Resolution: Na-document ang pag-inject ng `activity_logs` sa 2-second background sync payload, 
     pag-integrate ng Web Audio API synth sound, at live toast alerts."

IV. Q&A DEFENSE CHEAT SHEET (MGA POSIBLENG ITANONG SA DOCUMENTATION & SAGOT MO)
================================================================================

TANONG 1: "Bakit kailangan pa ng PHPDoc annotations kung self-explanatory naman ang function names?"
SAGOT MO:
"Bagamat malinaw po ang function names tulad ng `storeReservation()`, ang PHPDoc annotations 
po ay nagbibigay ng machine-readable metadata. Tinutukoy po nito ang exact class types 
ng parameters tulad ng `Request $request` at return types tulad ng `JsonResponse`. 
Nakatutulong po ito sa IDE code completion, static analysis tools (tulad ng PHPStan), 
at automated documentation generators upang maiwasan ang type mismatches at runtime bugs."

TANONG 2: "Ano ang kahalagahan ng pagdodokumento ng mga naging errors at incident logs?"
SAGOT MO:
"Napakalaki po ng halaga nito para sa Software Quality Assurance at Knowledge Management. 
Kapag na-document po ang sanhi ng error (tulad ng SQL duplicate key o OAuth mismatch) 
at ang exact step-by-step fix nito, hindi na mauulit ang parehong pagkakamali, 
at madaling mai-onboard ang sinumang bagong programmer sa aming team nang hindi 
nanghuhula sa codebase."

TANONG 3: "Saan makikita ng panel ang kumpletong listahan ng mga API endpoints ng inyong system?"
SAGOT MO:
"Nakalista po ito nang buo sa aming Master README.md file sa ilalim ng Section 5 (REST API 
& Endpoints Catalog). Naglalaman po ito ng lahat ng 21 HTTP routes, kasama ang kanilang 
methods, descriptions, at middleware protection tulad ng public access, OnePass verified session, 
at administrative privileges."
